# 미미르 스코어: 14종 전용 함수

현재 앱은 딜도로 서버 API 방식이며, 대상만 실제 육성, 동료 4명은 고정 육성, 연구실은 사용자 값을 공통 적용한다. 동기화 성공 후 서버에서 한 번 계산해 사용자별 DB에 저장하고, 프로필 조회와 순위 집계는 저장 결과만 읽는다. 2026-11-03 확정 편성 54종·속성별 56개를 계산 설정에 연결하고, 명중률·차지 속도의 정상 음수 옵션을 거부하던 문제를 수정했다. [현재 구현과 운영 반영 절차](../../docs/mimir-score-partner-api.md)를 참조한다.

아래는 이전 내장 계산기 기록이다. 고정 편성의 선정 근거는 새 API에서도 유지한다.

이전에는 웹앱에 내장된 전투 계산기에 선택한 니케의 실제 육성을 넣고 **개인 딜 × 5 ÷ 1억**을 반환했다. 화면은 자동 계산 후 `미미르 스코어 : 102.24` 형식 한 줄만 표시했다.

## 확정한 공통 기준

사용자의 2026-10-19 지시에 따라 **솔로레이드에서는 최다 조합과 보스 속성만 가져온다.** 시즌 보스의 스탯·패턴은 가져오지 않는다.

- 2026-10-19에 확보한 속성별 고정 시즌(S40·S41·S38·S36·S39) 표본의 최다 5인 조합과 최빈 배치를 사용한다. 2026-10-25 추가 대상도 같은 표본에서 선정했다. 신규 시즌으로 자동 교체하지 않는다.
- 배치 순서를 그대로 버스트 운용으로 해석하지 않는다. 평가 대상의 단계에서 본인을 우선 사용하고 쿨타임 중이면 동료를 사용한다. 그 외 2단계는 사용 가능한 동료를 배치 순으로 선택한다. 프리카 첫 사이클 등 다른 단계의 고유 패턴과 재장전 조작은 보존한다. 이 운용은 평가용 고정 정책이며 랭킹에서 가져온 실전 운용은 아니다.
- 적 속성을 해당 니케가 우월 코드 피해를 줄 수 있는 속성으로 설정한다. 오버로드 우월 코드 옵션과 캐릭터의 속성 효과는 실제 전투 계산에 반영된다.
- 모든 대상은 계산기의 동일한 공통 적 기준을 사용한다. 방어력31,784, 코어0, 파츠 없음, 거리 보정 없음이며 시즌별 스탯으로 바꾸지 않는다. 공격·무적·이동·파츠 파괴 패턴을 넣지 않는다.
- 400레벨·180초·기대값·seed0·첫 버스트3초·fixed 버스트 게이지. 사용자 실제 레벨·전투력은 평가 입력에서 제외한다.
- 대상 니케의 스킬·돌파·코어·호감도·장비·오버로드·큐브·소장품·연구실을 적용한다. 동료 4명의 육성은 고정한다.
- 라피도 같은 공통 조건으로 변경했다. 기존 S40 패턴 계산의 기준102.19점은 현재 버전의 기준값이 아니다.

## 구현

- `targets.json`: 14종 ID·name_code·속성·역할군·연구실·무기별 소장품 ID·평가 버전.
- `adapter.py`: 실제 육성을 정규화한다. 신데렐라·아니스 : 스타는 방어1102, 나유타·리틀 머메이드는 지원1103, 나머지는 공격1101 연구와 해당 역할군 장비를 사용한다. 제조사에 따라 엘리시온1201·미실리스1202·테트라1203·필그림1204 연구를 적용한다.
- `embedded.py`: 14종의 개별 `calculate_*_score` 함수와 name_code 기반 `calculate_nikke_score` 디스패처. 다른 니케의 스펙을 전용 함수에 넣으면 거부한다.
- `contexts/*common*.json`: 대상마다 최다 조합·동료 스펙·조작·공통 적·우월 속성·출처 해시를 고정한다.
- `lib/services/nikke_score_service.dart`: 현재 스펙을 전달하고, 진행 중 요청·결과를 최대32개 캐시한다.
- `lib/widgets/nikke_damage_card.dart`: 상세 화면 진입 시 자동 계산. 스펙 변경 시 갱신, 이전 계정 응답 무시, 점수 한 줄 표시. 계산 중 `…`, 정보 누락·미지원은 `—`.
- `lib/data/nikke_score_targets.dart`: `targets.json`에서 자동 생성한 화면 적용 대상 목록.

기존 스냅샷의 완전성 메타데이터가 없으면 저장된 명시적 필드를 검증해 계산한다. 알려진 수집 실패·필드 누락·미지원 큐브·장비·소장품은 기본 육성이나0점으로 대체하지 않는다. 예전 동기화가 채운 기본값의 원래 수집 상태는 복원할 수 없다.

## 앱 안에서 실행

고정 커밋의 원본 계산 엔진과14종 함수를 `web/score/rapi-engine.zip`에 묶는다. 기존 파일 경로를 유지했지만 내용은14종 공용이다. 웹 워커의 Pyodide0.29.3으로 실행하며 모든 파일은 웹앱 자체에서 제공한다. 계산 API·Cloud Run·CDN 요청은 없다. 워커는 완료·실패·3분 초과 시 종료한다.

전체 추가 정적 파일은 약13.6MB이며 계산 시 로드한다. 일반 Flutter Web 빌드에는 Python이나 별도 서버가 필요 없다. 네이티브 앱 런타임은 이번 범위 밖이다.

`score-reference.inputs.json`은 실제 계정이 아닌 합성 입력이다. `score-reference.results.json`에는 각 대상의 기준점수·코어2점수·우월 옵션 제거 점수와 버스트 사용 횟수를 기록한다. 검증에서는14종 모두 코어 강화 후 상승하고 우월 옵션 제거 후 하락해야 한다. 세 가지 육성 모두에서 대상 버스트 사용, 교대가 필요한 2단계 동료의 참여와 첫 사이클 전용 운용, 충분한 풀버스트 사이클을 실제 전투 로그로 검사한다. Chrome WASM 점수는 Python 결과와 같아야 한다.

### 버스트 운용 오류 수정 (2026-10-19)

이전 자동 운용은 2단계의 첫 캐릭터만 선택해 쿨타임 동안 전투 사이클을 지연시켰다. 그 결과 앞에 배치된 3단계 캐릭터가 매번 버스트를 사용하고 신데렐라·홍련 : 흑영은 한 번도 사용하지 않았다. 신데렐라 : 크리스탈 웨이브 조합도 두 번째 2단계 동료가 누락됐다. `target-b3-first-ready-b2-slot-order-v1` 정책으로 수정하고 평가 버전을 올렸다. 엔진의 빈 버스트 패턴은 사용 금지가 아니라 매 사이클 후순위 후보를 뜻한다. 이를 동료에게 명시해 쿨타임에 따른 교대를 허용한다.

동일한 합성 입력에서 신데렐라35.22→147.51, 홍련 : 흑영35.81→194.45, 신데렐라 : 크리스탈 웨이브117.00→169.83으로 변경됐다. 라피·스노우 화이트·도로시의 점수는 같았다. 당시 수정한 기존 여섯 대상 모두 180초 동안 버스트8회, 조합의 풀버스트15회를 확인했다. 이 수치는 사용자 계정의 재계산 결과가 아니다.

검증 명령은 위와 같다. 14종 등록·장비 및 연구실 매핑, 화면 자동 계산, 실제 엔진의 육성·우월 코드·버스트 로그, Chrome과 Python의 결과 일치를 확인한다.

Windows Flutter3.19.6 테스트가 한글 임시 경로에서 실패하면 해당 프로세스의 TEMP·TMP를 `scratch/flutter-temp` 절대 경로로 설정한다.

원본 엔진은 수정하지 않았다. 고정 커밋·라이선스·파일 해시는 `engine_lock.json`, `THIRD_PARTY_NOTICES.md`, `web/score/bundle-manifest.json`에 보존한다. 원시 랭킹의 계정 식별정보는 번들에 넣지 않는다. 예전 S40 패턴 환경 파일은 조사 기록으로 남기고 현재 웹 번들에서는 제외한다. 기존 CLI·HTTP 코드는 라피 개발 검증용이며 웹 화면에서 호출하지 않는다.

이 점수는 공통 평가 조건의 계산값이다. 실제 솔로레이드의 보스 패턴을 재현한 실전 딜량이 아니다. 운영 사이트 배포는 수행하지 않았다.
